# 阶段三：认知系数接入决策网络的失败诊断

## 实验链路

决策接收器已经通过 oracle probe 验证。这里冻结阶段二低秩认知模型，将其 `physics_coefficients` 经过可学习的线性 `PhysicsTransport` 后输入同一个决策网络，并与 state-only、oracle 对照。

认知模型使用系数一致性权重 0.1 的版本；决策目标与 oracle probe 相同，使用训练因素组合训练，在混合 held-out 因素上评估。

## 结果

| seed | 模式 | MSE | receiver 打乱后 MSE | 打乱增量 |
|---:|---|---:|---:|---:|
| 42 | state-only | 0.07574 | 0.07574 | 0.00000 |
| 42 | oracle | **0.04097** | 0.08285 | **0.04188** |
| 42 | cognitive | 0.07328 | 0.07330 | 0.00001 |
| 43 | state-only | 0.06997 | 0.06997 | 0.00000 |
| 43 | oracle | **0.04131** | 0.08524 | **0.04392** |
| 43 | cognitive | 0.07048 | 0.07051 | 0.00003 |

## 监督 transport 诊断

为了区分“坐标旋转问题”和“信息缺失问题”，额外用合成环境中的真实因素码监督 `PhysicsTransport(c)` 对齐 oracle 坐标。seed 42 的结果：

| 对齐权重 | 决策 MSE | transport 到 oracle 的 MSE |
|---:|---:|---:|
| 0.0 | 0.07360 | 0.72690 |
| 0.1 | 0.07334 | 0.24516 |
| 1.0 | 0.07332 | 0.24496 |

即使使用真实因素标签辅助，线性 transport 也无法把认知系数恢复为 oracle 坐标，决策网络仍忽略该输入。

## 结论

1. 决策接收器本身可用；oracle 物理码能显著改善决策，打乱码会破坏性能。
2. 当前认知系数对动力学预测有用，但对决策任务不是可直接解码的语义坐标；系数一致性只能改善轨迹稳定性，不能自动解决任务语义对齐。
3. 失败不是简单的线性 transport 初始化问题。当前 `c(h)` 可能编码了“足以预测下一状态”的坐标，而不是决策任务需要的坐标；这正是表示不可辨识性。

## 下一步

下一步进入联合任务对齐实验：保持动力学预测损失和反事实 gap 约束，同时让决策损失的梯度通过 transport 回传到认知系数；比较完全冻结、只训练 transport、认知—transport 联合训练三种模式。若联合训练损害物理预测，则需要显式共享/分离子空间或任务条件化的物理算子，而不是继续扩大决策头容量。
