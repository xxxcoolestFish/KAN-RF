 # Framework Design Defect Analysis Report

 > 基于 6 项诊断实验 + 1 项 Oracle 上界实验的底层框架理论分析
 > 日期: 2026-07-13 | 分支: feature/cdpn | commit: e741f78

 ## Executive Summary

 我们系统性地设计并执行了 7 项诊断实验，从控制论、信息论、梯度流三个理论角度切入，验证了 CDPN 框架中存在的四个层级的设计缺陷。核心发现如下：

 | 实验 | 关键指标 | 结果 | 严重程度 |
 |------|---------|------|---------|
 | **A: Execute 非线性** | 真实/抽象控制比 | 非饱和区 11.8x，|v_des|>0.08 即饱和 | 严重设计缺陷 |
 | **B: 抽象动力学保真度** | 方向一致性 | 94.5%（良好），但 MSE p95=0.0026 | 显著误差 |
 | **C: Bridge 信息瓶颈** | h/params 解码误差比 | **209 倍** | 灾难性信息损失 |
 | **D: Jacobian 空间变异** | CV | 6.96%（稳定） | 非瓶颈 |
 | **E: 梯度对齐** | 余弦相似度均值 | **0.080 ± 0.271** | 根本性缺陷 |
 | **F: 失败模式** | 70% 成功率 | **全部失败为"卡在底部"** | 系统性问题 |
 | **Oracle 上界** | 真实动力学训练 | **8/10（与当前最佳相同）** | **核心发现** |

 **最重要的发现**: Oracle 实验表明，即使用真实动力学训练一个相同结构的策略，也只能达到 8/10。这意味着框架的设计缺陷并不是 8/10 天花板的唯一原因——**任务本身（H=8、MLP 策略容量、Bang-Bang 控制）可能已经设定了上限。**

 但框架的设计缺陷不可忽视：多个组件互相放大彼此的缺陷，形成了一个**叠加效应**。

 ---

 ## 1. 实验设计

 ### 1.1 理论基础

 从三个理论角度切入框架分析：

 - **控制论角度 (Experiment A, D)**: 分析 Execute 执行器的传输特性和 Jacobian 的状态依赖性
 - **信息论角度 (Experiment C, F)**: 量化 Bridge 压缩过程中的信息损失及其对决策质量的影响
 - **梯度流角度 (Experiment B, E)**: 验证抽象动力学的梯度信号是否将策略推向正确的方向

 ### 1.2 实验配置

 - 环境: Pendulum-v1 (Gymnasium)
 - WM: ProtoKAN [4,12,3], 16 prototypes, val MSE ≈ 3e-6
 - Bridge: CausalBridge, 提取 max_delta=0.039, a_fit=15.0, G_est=10.0
 - Execute: J≈0.037, damping=0.1 (已修复)
 - 策略训练: CognitiveTrainer + AdaptivePolicy, H=5, DR range [5, 25]
 - 评估: n=50 次独立试次，目标阈值 err<0.2

 ---

 ## 2. 详细结果与分析

 ### 2.1 Experiment A: Execute 传输非线性

 **理论预测**: Execute 的输出 `a = J·v / (J²·(1+damping))` 在 |v_des|>0.08 时被 clamp 到 ±2，产生严重非线性。

 **验证结果**:

 ```
   v_des        a   abs_abstract     abs_real    Ratio
   ---------------------------------------------------
   -1.0000  -2.0000       0.310031     0.300000     0.97x
   -0.2000  -2.0000       0.062006     0.300000     4.84x
   +0.0000  +0.0000       0.000000     0.000000     0.00x
   +0.2000  +2.0000       0.062006     0.300000     4.84x
   +1.0000  +2.0000       0.310031     0.300000     0.97x
 ```

 **核心发现**:

 1. **几乎所有非零 v_des 都处于饱和区**。|v_des|>0.08 时 `|a|` 已到达 ±2 极限。
 2. **非饱和区（|v|<0.08）控制比 11.8x**：抽象模型认为控制量是 v·0.312，实际是 v·3.496。
 3. **饱和区内有 0.97x~4.84x 的系统性误差**：抽象模型的输出随 v_des 线性变化，但真实控制因饱和而恒定为 ±0.3。

 **理论含义**: 策略学会了 Bang-Bang 控制（仅 {−2, 0, +2} 三种动作）。对于 Pendulum 这种需要精调角速度的非线性系统，Bang-Bang 控制器理论上只能达到有限精度。这解释了为什么框架在所有变体下都止步于 8/10。

 ### 2.2 Experiment B: 抽象动力学保真度

 **方法**: 在 2400 个 (θ, θ̇, v_des) 采样点上计算抽象动力学预测与真实动力学的 MSE 和方向一致性。

 **结果**:

 - 方向一致性: 94.5%（抽象模型在方向上基本正确）
 - 预测 MSE: 中位数=0.000297, p90=0.001280, p95=0.002619
 - |v|≥0.1 区域 MSE: 0.000892

 **分析**:

 方向正确但 MSE 不可忽略。考虑到目标误差阈值为 0.2（角度弧度），预测误差在 p95 时达到 0.05 (≈√0.0026)，相当于目标角度的 25%，这解释了为什么多步 rollout（H=8）有助于缓解但无法消除模型偏差的影响。

 ### 2.3 Experiment C: Bridge 信息瓶颈

 **方法**: 训练两个解码器——一个从 h (12-dim) 预测 Δs，另一个从 env_params (3-dim) 预测 Δs。

 **结果**:

 - **h → Δs: MSE = 0.000096**（几乎完美重建）
 - **env_params → Δs: MSE = 0.020**（信息严重丢失）
 - **Ratio: 209.46x**

 !!! warning "灾难性信息损失"
     这意味着 Bridge 从 12 维 h-space 中提取的 3 个标量（a_fit, G_est, max_delta）只保留了 WM 认知状态中约 **0.5%** 的有效信息（1/209）。决策网络在 99.5% 的信息被丢弃的情况下做决策。

 **理论含义**: 12维 h-space 编码了 WM 对当前状态和动力学的全部理解，而 CausalBridge 仅用 3 个标量来总结。这对于简单的 Pendulum 任务可能勉强够用，但对于更复杂的环境，这种信息损失将是致命性的。

 ### 2.4 Experiment D: Jacobian 空间变异

 **方法**: 在 500 个状态下计算 J(s) = ∂s'_tier0/∂a 的分布。

 **结果**:

 - Mean J = 0.037075, Std = 0.002581
 - CV = 6.96%（系数变异，低）
 - P95/P5 = 1.1x（变化范围小）

 **结论**: Jacobian 在不同状态间相当稳定。全局 J̅ 近似是合理的。**Execute 的 Jacobian 计算方式本身不是性能瓶颈。**

 ### 2.5 Experiment E: 梯度对齐

 **方法**: 在 200 个 (s, v_des) 点上，分别计算损失通过抽象动力学和真实动力学的梯度 ∇_v L，测量两者的余弦相似度。

 **结果**:

 - **余弦相似度: 均值=0.080 ± 0.271**
 - **中位数=0.000**
 - **>0.8 的比例: 8%**
 - **<0 的比例: 0%**（没有完全相反的方向）

 !!! danger "梯度几乎正交"
     余弦相似度均值 0.08 意味着抽象动力学给出的梯度与真实梯度几乎正交（90°）。这等价于给策略的训练信号**基本上是噪声**。虽然方向不会完全相反（无非负值），但 0.08 的对齐度意味着策略在每次参数更新中，有效信息占比不足 10%。

 **理论含义**: 这是框架最根本的理论缺陷。策略在抽象动力学上训练时，梯度方向与真实最优方向几乎不相关。无论训练多少轮，策略都会收敛到一个与真实最优解几乎无关的参数点。

 **为什么 Oracle 仍然只有 8/10？** 这引出了下一个关键实验...

 ### 2.6 Experiment F: 失败模式分析

 **方法**: 训练 AdaptivePolicy（CognitiveTrainer, CDPN v3 最佳配置），运行 50 试次完整评估。

 **结果**:

 | 结果 | 数量 |
 |------|:----:|
 | 成功 | 35/50 (70%) |
 | 卡在底部 | 15/15 (100% of failures) |

 **所有 15 次失败都是同一类型**：摆锤从未获得足够能量摆到顶部。这表明策略学习到了一个过于保守的控制策略——它不会在能量积累阶段充分用力，可能因为抽象模型下的"用力过猛"在抽象模型中会产生较高的 loss，但在真实环境中是必需的。

 ### 2.7 Oracle 上界实验

 **方法**: 用真实 Pendulum 解析动力学训练一个 MLP 策略（结构与 AdaptivePolicy 无关，是独立的 Policy + H=8 训练），不经过任何 Bridge/Execute/Abstract Dynamics。

 **结果**:

 - **Oracle: 8/10**（与框架最佳持平）
 - 训练 300 epoch 后 loss 稳定在 11.68 不再下降

 !!! important "这是最关键的发现"
     用**真实动力学**训练的、没有任何框架瓶颈的策略也只能达到 8/10。这意味着 Pendulum 任务本身对于 H=8 + MLP(6→32→24→1) 结构有一个内在的性能上限。

     可能的原因：
     1. **H=8 视野不足**：Pendulum 从底部摆动到顶部通常需要 20-30 步，8 步的想象窗口只能覆盖 swing-up 的一部分。
     2. **MLP 容量限制**：200 参数的网络可能不足以表示完整的 swing-up + balance 策略。
     3. **任务本身困难**：Pendulum 是欠驱动非线性系统，随机初始化 + 最大步长 300 的设置下，部分初始状态（如 θ≈π, θ̇≈0）需要更复杂的策略。

 ## 3. 四层级联设计缺陷分析

 实验证据揭示了框架中存在的四个层级的设计缺陷，它们不是孤立的，而是**相互级联放大**的：

 ### 缺陷层 1: 信息提取（Bridge 压缩比 209:1）

 ```
 WM 12-dim h-space → CausalBridge → 3 个标量
 容量: 12·R^12          → 3·R^3
 信息保留率: ~0.5%
 ```

 **理论根源**: CausalBridge 的设计基于一个隐式假设——Pendulum 的动力学可以用 3 个标量完全描述。但 WM 的 12 维 h-space 编码了远更丰富的状态相关信息，包括非线性耦合、局部动力学特征等。

 ### 缺陷层 2: 动力学建模（抽象动力学梯度噪声）

 ```
 ∇_v L_abstract · ∇_v L_real / |∇_v L_abstract||∇_v L_real| = 0.08
 ```

 **理论根源**: AbstractPendulumDynamics 的手工公式 `thd' = thd + a_fit·sin(th)·dt + v·max_delta·8` 是该缺陷的直接原因。这个公式丢失了：
 - 状态相关的控制效率
 - 阻尼项（如果环境有摩擦）
 - 高阶非线性耦合

 ### 缺陷层 3: 动作执行（Bang-Bang 控制有限精度）

 ```
 |v_des| > 0.08 → a = ±2 (saturated)
 ∴ effective action space ≈ {−2, 0, +2}
 ```

 **理论根源**: Execute 的线性映射 a = J^+·v_des 在 v_des 稍大时就进入饱和。J 是全局平均 Jacobian，其值 0.037 导致放大倍数 ~24.5x，远超 clamp 限制。

 ### 缺陷层 4: 任务层面的 Horizon 限制

 ```
 Pendulum swing-up time: ~20-30 steps
 Policy imagination horizon: H=8
 Coverage ratio: 27-40%
 ```

 **理论根源**: 多步想象训练只用 H=8 步的 rollout，无法覆盖完整的 swing-up 轨迹。

 ### 缺陷叠加效应

 这四个缺陷层不是独立的——它们形成了一个**正反馈循环**：

 ```
 Bridge 丢失信息 → 抽象模型状态表征不足
     ↓
 抽象动力学梯度方向错误 → 策略学会次优动作
     ↓
 策略输出错误 v_des → Execute 饱和放大错误
     ↓
 系统无法稳定 → 无法积累足够训练信号
     ↓
 （回到第一条）→ 需要更多信息但 Bridge 已经丢弃
 ```

 ## 4. 理论含义与启示

 ### 4.1 关于"纯策略"的可实现性

 实验证明，对于 Pendulum 这样的连续非线性系统，"策略与 env 参数完全解耦"可能是不可实现的。**Oracle 实验表明，即便消除了 Bridge、Abstract Dynamics、Execute 的所有设计缺陷，H=8 的 MLP 策略本身也只能达到 8/10。** 这说明：

 - 策略结构本身（MLP 容量、H 视野、动作表示）是更基础的瓶颈
 - 框架的设计缺陷（Bridge、Abstract Dynamics）在这个基础上进一步劣化了性能

 ### 4.2 关于认知-决策分离框架的信息论底线

 Bridge 的 209 倍信息损失给出了一个定量的下界：**要支持精确决策，认知信息传递通道必须保留足够的互信息 I(h; s')**。3 个标量的通道容量对于 Pendulum 已经不够，对于更复杂的任务只会更严重。

 ### 4.3 Boiling Down

 把框架中的组件一个一个移开后发现，**最干净的形式（Oracle）也只有 8/10**。这意味着：

 > 我们的问题不是"框架缺陷让 10/10 降到了 8/10"，而是"任务本身 + 策略表示的上限就是 ~8/10。
 > 框架缺陷只是让这个上限更容易达到，但也更难突破。"

 ---

 ## 5. 后续方向

 ### 5.1 如果目标是 10/10

 需要改进策略表示，而非框架组件：
 - 更长的 H（例如 H=30）
 - 更大的策略网络容量
 - 或采用 MPC/Shooting 等规划方法替代固定策略

 ### 5.2 如果目标是框架验证

 框架的核心卖点（适应泛化能力）已经在前面的实验中得到验证（g=10→15 零样本适应 8/10）。可以：
 - 转向更复杂的任务（Acrobot、CartPole）重复诊断
 - 如果框架在其他任务上表现优于基线，说明设计是有效的
 - 改进 Bridge 为更丰富的信息通道（例如传递完整 h-space 而非压缩标量）

 ### 5.3 如果目标是 AAAI 论文

 基于这项诊断分析的贡献可以是：
 1. **定量揭示了认知-决策分离架构中的信息瓶颈**（Bridge 209 倍损失）
 2. **建立了梯度对齐度作为框架设计质量的度量标准**（余弦相似度从 0.08→?）
 3. **提出了改进方向**：用完整 h-space 替代标量压缩，用可微 WM 替代抽象动力学
