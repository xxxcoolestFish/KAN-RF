## 当前进度：我们在做什么

### 核心研究问题

**KAN 的 B-样条局部支撑能否使世界模型在部署中安全地在线适应——不需要 MLP 所需的 replay buffer / ensemble / meta-learning？**

### 系统架构

```
执行循环:
  1. 当前状态 s → 能量引导单步优化 → 动作 a
     (min_a (E(f_KAN(s,a)) - E_des)^2，50 iters Adam，单步不嵌套)
  2. 执行 a，监控 ||s_real - f_KAN(s,a)||
  3. 每步三因子在线学习 (eta0=1e-3)
  4. 偏差 > 阈值 → Smart Burst:
     用模型自己的决策测试模型（5步 + 5轮重复学习, eta×20）
  5. 到达目标 (|Δθ| < 0.2) → 成功
```

### 工程优化（巨大提速）

- **B-样条向量化**（`bspline.py`）：消除 Cox-de Boor 内层 Python for-loop → 3× 加速
- **kan_layer 批量处理**：所有输入维度一次性计算 B-样条
- **CPU + torch.compile**：发现小 KAN 在 CPU 上比 MPS 快 **33 倍**（0.16ms vs 5.3ms per forward）
  - MPS 对小模型有 kernel launch 开销，CPU 无此开销
- **Batch-parallel shooting**：多 restart 并行优化（GPU batch 维度）

### 卡在 8/10 的原因

两个失败的 trial 都是底部起步（|Δθ₀| > 4 rad）：
- Trial 2: cos≈-0.99, sin≈-0.14, thd=-0.79, |Δθ|=4.57
- Trial 3: cos≈-0.86, sin≈-0.52, thd=+0.74, |Δθ|=4.17

**"模型诚实"问题**：v6 在底部很准（model_err~0.1），正确预测单步能量几乎不变 → optimizer 不做大动作 → 摆不起来。
单步能量引导无法推理多步累积 pumping 效应。

## 容易理解偏差的内容

1. **"模型诚实"问题不是 bug**
   模型准确 → 单步能量预测真实 → 动作保守。这是正确行为，问题在单步方法的视野限制，不在模型。

2. **Smart burst ≠ 随机探索**
   随机 burst（exp_E）是无目的的。Smart burst（exp_F）是"用模型自己的决策测试模型"，在模型犯错的精确位置做高学习率修正。

3. **Replanning 破坏连贯性**
   任何形式的 replanning（包括 K>1）都是在解新问题。完美模型下 open-loop H=30 成功，但只要 replan 就失败。这是根本性的，不是调参能解决的。

4. **KAN 的两面性：可微 + 局部**
   - 决策时：B-样条可微 → 梯度穿过 KAN 到动作空间
   - 学习时：B-样条局部支撑 → 更新只影响激活区域
   两者不矛盾，来自同一个 B-样条基函数的不同属性。

5. **B-样条激活密度是免费的不确定性信号**
   不需要额外训练 ensemble 或 uncertainty network。输入落在训练分布外 → B-样条激活稀疏 → 自动检测。

6. **CPU 比 MPS 快不是因为 GPU 不行**
   模型太小（756 params），GPU kernel launch 开销占主导。torch.compile 在 CPU 上融合了 Python 循环，反而更快。如果模型更大，GPU 优势才会体现。

7. **实验 D/E/F/G 不是完全干净的 ablation**
   每个实验用了不同的 burst 机制、预热方式、参数设置。直接对比成功率有局限性，但整体趋势可信（F > E > D，G 没超过 F）。

8. **KAN 架构**：[4→12→3]（或 [4→6→3]），输入 [cosθ, sinθ, θ̇/8, torque/2]，输出 [cosθ', sinθ', θ̇'/8]，grid=5, order=3
