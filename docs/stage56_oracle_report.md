# Stage 56：真实目标动力学 Oracle 实验

## 1. 实验目的

本实验用物理环境中的真实可微转移函数替换认知网络，检验在“物理规律完全正确”的情况下，现有决策网络能否完成参数变化后的任务。

Oracle 只提供接口：

\[
\hat{s}_{t+1}=f_{\theta}(s_t,a_t)
\]

决策网络没有直接接收重力、阻尼、驱动或惯量参数。

## 2. 实现方式

`OracleCognitive` 内部调用 `physics_transfer.variants.step`，并实现与认知网络相同的：

```python
forward(state, action, context) -> next_state
```

源环境训练阶段使用源动力学 Oracle；切换到 heldout 参数组 B 时，将同一个冻结 Oracle 的内部转移函数切换为目标动力学。认知网络不更新，在线阶段只更新决策网络 PPO 参数。

代码：

- `scripts/stage56_oracle_ppo.py`
- `scripts/stage56b_oracle_ppo.py`

## 3. seed=0 完整协议结果

| 阶段 | 成功率 |
|---|---:|
| 源环境训练后 | 78.13% |
| 目标动力学零样本 | 9.38% |
| 真实目标动力学 + 在线决策更新 | **32.81%** |

## 4. 结论

1. **决策网络可以利用准确的目标动力学信息。** Oracle 在线阶段从 9.38% 恢复到 32.81%，说明决策网络不是完全无法使用物理预测。
2. **认知预测误差不是当前唯一瓶颈。** Oracle 的最终结果与历史上下文认知网络约 30% 的结果接近；即使物理模型完全正确，策略仍然没有接近 100%。
3. **问题进一步集中到决策机制。** 当前单点动作查询、短期预测特征和 PPO 在线更新，仍不足以把完整动力学规律转换成长程有效动作序列。
4. **当前实验不能证明公式图接口无效。** 它只证明“给出准确的单动作后果”仍不够；下一步需要 Oracle 多动作接口，检验决策网络是否需要比较多个动作的后果。
