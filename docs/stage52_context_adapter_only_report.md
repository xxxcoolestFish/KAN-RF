# Stage 52：仅更新历史上下文编码器的在线适应实验

## 1. 实验目的

Stage 51 将历史转移编码成上下文向量，并在参数变化后在线更新整个认知网络。结果显示上下文确实能够识别新动力学，但认知损失在切换初期出现明显峰值，提示 ProtoKAN 核心和上下文编码器同时更新可能相互干扰。

本实验冻结预训练后的 ProtoKAN 核心参数，只允许 GRU 历史上下文编码器通过真实环境转移进行在线预测损失更新，检验“稳定上下文适配”是否能够改善泛化恢复。

## 2. 结构与协议

- 认知网络：`ContextCognitiveKAN`
  - GRUCell 输入 `[s_t, a_t, s_{t+1}]`
  - 隐状态维度 8，作为动力学上下文 `c_t`
  - ProtoKAN 输入 `[s_t, a_t, c_t]`，输出 `\hat{s}_{t+1}`
- 决策网络：ContextFiLM actor
  - 输入当前物理状态和上下文
  - 查询分支只生成 FiLM 调制
  - 决策头接收调制后的认知预测、预测残差和目标，不直接接收 query，避免绕过认知分支
- 预训练：单一源动力学环境的转移序列
- 决策预训练：源环境 PPO
- 泛化测试：切换到第二组动力学参数，先测零样本成功率，再用真实转移在线适应 30 个 episode/iteration
- 三个随机种子，固定初始状态协议，难参数组 B

## 3. 结果

| 方法 | 源环境成功率 | 参数组 B 零样本 | 在线适应后 |
|---|---:|---:|---:|
| 全量认知更新（Stage 51） | 86.46% ± 4.51 | 14.58% ± 3.25 | 30.21% ± 1.77 |
| 仅上下文编码器更新（Stage 52） | 86.46% ± 4.51 | 14.58% ± 3.25 | 29.69% ± 5.41 |

Stage 52 各种子在线最终成功率为 32.8%、32.8%、23.4%。其在线预测损失在三个种子中均平滑下降，未出现 Stage 51 中的约 `2e-2` 突发峰值；例如 seed 0 从 `1.28e-3` 降至 `2.87e-4`。

## 4. 结论

1. **上下文编码器确实在起作用。** 仅更新上下文仍能把硬参数组的成功率从约 14.6% 提升到约 29.7%，因此历史转移中包含可用于动力学识别的信息。
2. **冻结 ProtoKAN 主要改善稳定性，而不是平均性能。** 平均最终成功率略低于全量更新（29.69% 对 30.21%），且 seed 2 明显较低，说明纯上下文适配的表达容量不足。
3. **核心问题已进一步收敛。** 当前瓶颈不是“有没有上下文”，而是“如何在不破坏已学物理表征的情况下，给上下文足够的适配自由度”。

## 5. 下一步

采用混合更新：保持 ProtoKAN 主干冻结，只加入小容量、低学习率的动力学适配器（例如最后一层的低秩/门控残差），同时训练历史上下文编码器。这样可在稳定性和适应容量之间取得平衡，并与全量更新、纯上下文更新形成完整消融。
