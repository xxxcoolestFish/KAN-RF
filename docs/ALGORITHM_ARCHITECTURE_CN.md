# KAN-RF 算法架构通俗讲解

> 最后更新：2026-07-25

---

## 0. 一句话说清楚我们在做什么

**在标准物理环境训练一个走路机器人，部署到物理参数已改变的世界后，不让它重新训练策略，只让它通过观察"我做了动作 a，状态从 s 变成了 s'"来更新对世界物理的认知，然后用这个更新后的认知直接修正动作，从而快速恢复走路能力。**

---

## 1. 问题设定

### 训练时（源环境）

我们有一个 Hopper（单腿跳跃机器人），在**标准物理参数**下用 PPO 训练：

```
源物理：质量=1.0, 摩擦=1.0, 执行器力度=1.0
```

训练完成后，得到了两样东西：

- **源 Actor π₀(s)**：在标准物理下，看到状态 s，输出最优动作 a
- **源认知模型**：理解"在标准物理下，动作如何影响状态"

### 部署后（目标环境）

物理参数**偷偷变了**，但算法不知道变成了什么：

```
目标物理（例如 combo_medium）：质量=1.35, 摩擦=0.70, 执行器=0.75
```

算法必须**仅凭观察 (s, a, s')** 来适应，不能读取物理参数。

---

## 2. 为什么不直接继续训练 PPO？

继续训练 PPO 需要**目标环境的大量奖励信号**。但：
- 变化后的初始性能可能非常差（combo_medium 零样本只有 340，源环境有 3545）
- 收集足够奖励需要大量交互
- 奖励告诉我们"做得好不好"，但不直接告诉我们"物理规律变成了什么样"

所以我们走另一条路：**先更新世界模型（只需要 s, a, s'，不需要奖励），再把更新后的物理知识转化为动作修正。**

---

## 3. 核心架构：三层结构

```
┌─────────────────────────────────────────────────────┐
│                    源 Actor π₀                       │
│                   （冻结，不更新）                     │
│                 输入 s → 输出 a₀                      │
└──────────────────────┬──────────────────────────────┘
                       │  a₀ = π₀(s)
                       ▼
┌─────────────────────────────────────────────────────┐
│               控制等价认知接口                         │
│                                                     │
│   ┌──────────────┐    ┌──────────────────┐          │
│   │ 源数字孪生    │    │ 目标 ProtoKAN     │          │
│   │ f̂₀(s, δa)    │    │ f̂ₜ(s, δa)        │          │
│   │              │    │                  │          │
│   │ "如果在源物理  │    │ = b₀(s) + Φ(s)Wₜ │          │
│   │  下做 δa，    │    │ + G₀(s)Tₜ·δa    │          │
│   │  状态会怎么变" │    │                  │          │
│   │              │    │ "在当前物理下做    │          │
│   │ 给出反事实     │    │  δa，状态会怎么变" │          │
│   └──────────────┘    └────────┬─────────┘          │
│                                │                    │
│                    控制等价反解  │                    │
│                    ┌───────────▼──────────┐         │
│                    │ δa = argmin ‖f̂ₜ(s,δa)│         │
│                    │           - e₀(s)‖²  │         │
│                    └───────────┬──────────┘         │
└────────────────────────────────┼────────────────────┘
                                 │
                    ┌────────────▼──────────┐
                    │   最终动作              │
                    │   a = clip(a₀ + δa)    │
                    └───────────────────────┘
```

## 4. 逐模块详解

### 4.1 源 Actor π₀(s)

```
输入：11 维状态（关节角度、速度等）
输出：3 维动作（髋、膝、踝的力矩）
训练：PPO，源物理环境，~2M 步
性能：源物理下 3545 分，100% 健康完成率

为什么冻结它：
- 为了归因——"性能提升到底来自认知更新还是策略自己学好了？"
- 冻结 Actor → 任何改善都只能来自认知更新
```

### 4.2 源数字孪生 f̂₀(s, δa)

这是**最关键的模块之一**，但在最终论文中容易被忽略。

```
作用：回答"如果还在标准物理下，做一个动作扰动 δa，状态会怎么变？"

数学形式：f̂₀(s, δa) = b₀(s) + G₀(s)·δa

  b₀(s)：在状态 s 执行源策略动作 a₀ 时，状态会怎么变（基准漂移）
  G₀(s)：动作扰动 δa 对状态增量的局部影响矩阵（控制增益）

训练方式：
- 收集源环境中的 (s, a, s') 数据
- 在 a₀ 附近施加小的对称扰动，用有限差分估计真实 G(s)
- 用 Sobolev 训练同时拟合 b₀ 和 G₀

验证指标（Hopper）：
- 状态增量归一化 RMSE：~0.196
- 动作 Jacobian 余弦：~0.989
```

**为什么需要它？** 因为部署后我们不知道"在目标物理下状态变了是因为物理不同还是本来就会这样变"。源孪生给出了**反事实参照**——"如果物理没变，这个动作会导致什么效果"。

### 4.3 目标 ProtoKAN f̂ₜ(s, δa)

这是**在线更新的核心**。

```
数学形式：f̂ₜ(s, δa) = b₀(s) + Φ(s)·Wₜ + G₀(s)·Tₜ·δa

三部分解释：

① b₀(s)：源漂移（冻结，不更新）
    ↓ "在标准物理下，做 a₀ 后状态的基础变化"

② Φ(s)·Wₜ：目标漂移修正（在线更新，核心）
    ↓ "物理变化导致的基础漂移差异"
    Φ(s)：固定的 KAN 字典（551 维特征，包含 B-spline + 状态对交互）
    Wₜ：在线拟合的低维系数矩阵
    每收到一批新 (s,a,s')，用递归最小二乘更新 Wₜ

③ G₀(s)·Tₜ·δa：目标控制效果（在线更新）
    ↓ "动作对状态的影响力变化了多少"
    Tₜ：全局控制变换矩阵（Hopper 3×3，Walker2d 6×6）
    从控制差异中分离出漂移差异，再单独拟合 Tₜ
```

**谱正则化（最近新增）**进入的位置：拟合 Wₜ 时，不再用统一的正则化强度 λ=100，而是按 Φ(s) 的特征方向分别加权：

```
数据多的方向（大特征值）→ 弱正则化，信号自由通过
数据少的方向（小特征值）→ 强正则化，噪声被压制
```

### 4.4 控制等价动作运输

这是**从"知道物理变了"到"修正动作"的桥梁**。

```
步骤：

1. 计算源策略意图的标准效果：
   e₀(s) = f̂₀(s, 0)
   = "在标准物理下，执行源策略动作后，状态预期怎么变"

2. 在目标认知下反解：
   δa★ = argmin_δa ‖f̂ₜ(s, δa) - e₀(s)‖² + λ‖δa‖²
   = "需要多少动作修正，才能在当前的物理下
      复现标准物理下的效果？"

3. 最终动作：
   aₜ = clip(π₀(s) + δa★)
   = "源策略动作 + 认知修正 = 适应新物理的动作"
```

**关键设计**：认知位于动作生成的必经路径。不能绕过——认知模型的输出**直接决定了动作修正**。这就是为什么论文的 first-order claim 是"接口本身"，而不是"预测更准"。

## 5. 完整管道

```
【源阶段：只在标准物理下训练，一次完成】

Step 1: 训练源 PPO Actor
  scripts/train_hopper_sb3_ppo.py
  输出：hopper_source_sb3_ppo_continued_seed1811.zip

Step 2: 构建策略中心化 ProtoKAN 字典
  scripts/validate_hopper_centered_protokan_cognition.py
  输出：hopper_source_centered_protokan_seed1811.pt

Step 3: Sobolev 控制校准（训练 b₀, G₀）
  scripts/train_hopper_control_sobolev_cognition.py
  输出：hopper_source_control_sobolev_calibrated_seed1811.pt

Step 4: 训练 Dense 源数字孪生
  scripts/train_hopper_source_affine_twin.py
  输出：hopper_source_affine_twin_cloud_seed1811.pt

────────────────────────────────────────────────

【目标阶段：部署后，每预算独立运行】

Step 5: Warmup 探索
  - 在目标环境中执行 π₀(s) + 对称噪声扰动
  - 收集 N 条转移 (s, a, s')
  - 不求高回报，只为探索状态-动作空间

Step 6: 拟合目标认知
  - 源孪生给出反事实参照 Δŝ₀
  - 计算物理 gap: y = (s' - s) - Δŝ₀
  - 分离控制差异 → 拟合 Tₜ
  - 剩余漂移差异 → 拟合 Wₜ（谱正则化）
  - 构造 f̂ₜ(s, δa)

Step 7: 评估
  - 用 f̂ₜ 做控制等价运输 → 修正动作
  - 在目标环境跑 M 个 episode
  - 记录回报曲线
```

## 7. 关键设计选择

### 为什么用控制仿射形式 b(s) + G(s)·δa？

因为它把"物理变化的影响"自然地分解为两个可解释的部分：
- **b(s) 变化** = 重力/质量变化导致的状态漂移
- **G(s) 变化** = 执行器/摩擦变化导致的控制效力变化

这两部分可以**分开估计**（Tₜ 先估计，Wₜ 后估计），互相不污染。

### 为什么用 KAN 字典 Φ(s) 而不是端到端网络？

Φ(s) 固定不更新，只有 Wₜ 在线学习。这保证了：
- 在线更新是**线性最小二乘**（快、稳定、有闭式解）
- 非线性表达能力由 Φ(s) 的 B-spline 基础提供
- 不会发生神经网络灾难性遗忘

### 为什么冻结 Actor？

为了严格归因。如果允许 Actor 更新，评审会问"提升到底来自认知还是来自策略继续训练？"冻结 Actor 回答了这个问题。长期目标允许 Actor 更新，但必须先通过消融证明认知的独立贡献。
