# 当前框架细节（中文审查版）

> 文档目的：以当前代码和已经完成的修正实验为准，说明系统真实的模块边界、数据流、训练流程和已验证结论。
>
> 特别说明：本文将“已经实现的结构”和“计划中的理想结构”分开描述，避免把论文设想误写成现有代码。

## 1. 一句话概括

当前系统是一个“冻结任务策略 + 物理参数残差解码器 + 物理条件路由”的决策系统：

1. 教师控制器在指定物理环境中生成动作规律；
2. 任务主干学习与具体重力参数无关的摆动/平衡策略；
3. 物理专家学习不同物理条件下对任务主干的动作残差；
4. 认知世界模型通过预测下一状态来提取物理变化编码；
5. 路由器根据物理编码激活相应的物理专家；
6. DAgger 使用决策网络自己的闭环轨迹继续修正物理专家。

当前实现仍然是“认知编码器与决策网络半解耦”的版本：认知编码已经可以生成路由码，但还没有与决策网络进行完全端到端联合训练。

## 2. 当前真实的数据流

```mermaid
flowchart LR
    A[物理环境
    corrected Acrobot] --> B[状态 s_t
    6维归一化状态]
    A --> C[下一状态监督
    s_{t+1}]
    C --> D[世界模型
    ProtoKAN 7->16->6]
    D --> E[探针差分
    相对名义模型]
    E --> F[ProbeEncoder/PCA
    物理编码 z_phys]
    F --> G[路由码 c
    当前为一维标量]

    B --> H[任务主干
    ProtoKAN 6->24->1]
    B --> I[物理专家
    ProtoKAN 6->24->1]
    G --> J[B样条局部路由]
    I --> J
    H --> K[任务logit + 物理残差]
    J --> K
    K --> L[tanh动作 a_t]
    L --> A

    A --> M[教师控制器/CEM]
    M --> N[教师logit]
    N --> O[模仿学习 + DAgger]
    O --> I
```

实际使用时，决策网络的输入主要还是状态 `s_t` 和一个外部提供的物理路由码 `c`。世界模型不是每一步都在决策网络内部自动反向传播更新，而是先独立训练并提取编码。

## 3. 环境和动力学层

实现文件：`experiments/acrobot_corrected.py`

### 3.1 状态表示

状态为 6 维：

```text
s = [cos(theta1), sin(theta1), cos(theta2), sin(theta2),
     dtheta1 / 6.0, dtheta2 / 8.0]
```

其中：

- 第一杆角度为 `theta1`；
- 第二杆相对角度为 `theta2`；
- 角速度分别使用 `MAX_V1=6` 和 `MAX_V2=8` 归一化；
- 状态中没有直接放入重力参数。

### 3.2 动力学和动作

当前使用修正后的 Acrobot book-variant 动力学：

- 连杆长度：`L1=L2=1`；
- 质心位置：`LC1=LC2=0.5`；
- 转动惯量：`I1=I2=1`；
- 积分步长：`DT=0.05`；
- 连续动作：`a∈[-1,1]`；
- 速度限制：第一杆 `[-6,6]`，第二杆 `[-8,8]`；
- 目标条件：杆端高度 `tip_height > 1.0`；
- 单个 episode 最多运行 500 步。

初始状态的两个角度从 `[-0.1,0.1]` 均匀采样，初始角速度为 0。

### 3.3 重要历史修正

旧 V8–V14 使用的动力学方程存在重力项符号和速度耦合错误。旧版本在零动作下也可能得到不合理的 20/20，因此旧结果不能作为当前论文证据。V16 之后的结果全部使用 `acrobot_corrected.py`。

## 4. 教师控制器

实现文件：`experiments/v17_evolution_teacher.py`

### 4.1 教师不是神经网络

当前修正管线使用 CEM（Cross-Entropy Method）搜索一个低维线性反馈控制器。教师特征为 9 维：

```text
[dtheta1, dtheta2,
 sin(theta1), cos(theta1),
 sin(theta2), cos(theta2),
 sin(theta1+theta2), cos(theta1+theta2),
 tip_height / 2]
```

教师动作由下式产生：

```text
logit_teacher(s, g) = 3 * <w_g, features(s)>
a_teacher = tanh(logit_teacher)
```

每个重力参数 `g` 单独搜索一组 `w_g`。CEM 使用 20 个固定初始状态、500 步 horizon，并以成功 episode 数和平均最高高度共同评分。

### 4.2 教师的上限作用

教师不是理想控制器，因此学生不可能稳定超过教师上限。当前固定评估中：

- `g=7.35, 9.8, 11.0, 12.25, 13.475, 14.7` 的教师为 20/20；
- `g=17.15` 的教师为 18/20。

所以 `g=17.15` 不能简单要求学生达到 20/20。

## 5. ProtoKAN 基础网络

实现文件：`kanrf/_protokan.py`

当前任务网络和物理专家都使用 `ProtoKAN([6,24,1], n_prototypes=16)`。

### 5.1 单条边的原型插值

每条边使用一组可学习原型位置、原型值、原型导数和核宽度：

```text
w_n(x) = softmax(-(x-p_n)^2 / (2*sigma^2))

phi(x) = sum_n w_n(x) * [y_n + d_n * (x-p_n)]
```

同时保留一个 SiLU 基础路径：

```text
y = sum_i phi_i(x_i) + SiLU(x) @ W^T
```

因此 ProtoKAN 的可解释性来自：

- 每条输入到输出边拥有独立的原型函数；
- 原型位置可以学习；
- 可以读取边激活和边能量；
- 可以分析不同物理专家的梯度责任。

当前实验没有证明 ProtoKAN 的成功率显著优于参数量匹配的 MLP。当前更可靠的创新点是局部物理责任分配和可解释适应机制。

## 6. 任务主干和物理解码器

### 6.1 任务主干

任务主干为：

```text
task_surface: ProtoKAN(6 -> 24 -> 1)
```

它只接收物理状态 `s`，输出名义任务动作的 logit：

```text
l_task = f_task(s)
```

在 V19 中，任务主干只用 `g=9.8` 教师闭环轨迹训练，然后冻结。这样可以检验后续物理专家是否真的承担了物理变化，而不是让整个网络重新学习每个环境。

### 6.2 物理路由码

当前 oracle 路由码是重力的归一化标量：

```text
c_oracle = clamp((g - 9.8) / 2.45, -2, 2)
```

当前训练重力：

```text
TRAIN_GRAVITIES = [7.35, 12.25, 14.7]
```

测试重力：

```text
TEST_GRAVITIES = [9.8, 11.0, 13.475, 17.15]
```

### 6.3 局部物理专家

V19 的局部策略为：

```text
physics_grid = [-2, -1, 0, 1, 2]
```

`c=0` 对应名义环境，因此该位置的 B 样条基函数被视为 reference basis，不对应独立物理专家。实际使用 4 个物理专家，对应非 reference 的局部基函数。

物理残差为：

```text
l_phys(s,c) = sum_i B_i(c) * e_i(s)
```

最终决策 logit 为：

```text
l(s,c) = l_task(s) + l_phys(s,c)
a(s,c) = tanh(l(s,c))
```

因此：

- 在 `g=9.8`、`c=0` 时，物理残差为 0；
- 在已训练物理节点附近，主要激活局部专家；
- 在未见插值点，多个邻近专家会共同参与；
- 在 `g=17.15`，路由码被截断到 `c=2`，属于边界外推而不是正常插值。

### 6.4 当前 V27 诊断扩展

V26/V27 临时在 `g=11.0` 和 `g=13.475` 增加了两个专属残差专家，用来诊断参数覆盖不足。这两个专家只训练物理残差，任务主干和旧专家保持冻结。

它们不是最终模型结构，而是一个诊断干预：如果专属专家能够降低插值点的动作误差，就说明原有 B 样条插值覆盖不足。

## 7. 认知世界模型和物理编码

实现文件：

- `experiments/v22_corrected_world_model_encoder.py`
- `experiments/v22b_corrected_world_model_encoder_adapt.py`
- `experiments/v23_corrected_cognitive_interface.py`

### 7.1 世界模型

世界模型为：

```text
world_model: ProtoKAN(7 -> 16 -> 6)
```

输入为：

```text
[state(6), action(1)]
```

输出为预测的下一状态：

```text
hat{s}_{t+1} = M_phi(s_t, a_t)
```

训练目标为修正动力学产生的真实下一状态 `s_{t+1}`。

### 7.2 探针编码

当前世界模型编码不是直接读取某个单一物理参数，而是：

1. 训练名义重力 `g=9.8` 的世界模型；
2. 在其他重力下对名义模型进行微调；
3. 在固定 probe states/actions 上计算模型输出相对于名义模型的差分；
4. 将差分展平为物理变化 signature；
5. 使用 SVD/PCA 提取二维低维编码；
6. 通过重力相关性确定第一主成分的方向；
7. 对编码做标准化，再转换为策略路由所需的标量码。

当前 probe 数量为：

```text
9 个 theta1 点 × 3 个 theta2 点 × 3 个速度点 × 3 个动作点 = 243 个 probes
```

### 7.3 当前认知接口的真实状态

当前 Cognitive code 有以下限制：

- 需要已知重力标签来训练/微调对应世界模型；
- 世界模型和策略没有端到端联合优化；
- ProbeEncoder 使用离线 SVD/PCA，而不是神经网络在线推断；
- V23 只是将提取的 code 接入已有局部路由器；
- 目前还没有证明该编码可以在完全未知、持续变化的环境中稳定在线生成。

因此，当前结果应描述为“认知世界模型驱动物理路由的半端到端验证”，而不是完整端到端认知决策系统。

## 8. 训练流程

### 8.1 阶段 A：训练任务主干

在 V19 中：

1. 使用 `g=9.8` 教师闭环轨迹；
2. 收集名义任务状态；
3. 用教师 logit 训练 `ProtoKAN(6,24,1)`；
4. 冻结任务主干。

### 8.2 阶段 B：训练物理专家

对每个训练重力：

1. 生成约 20,000 个随机状态；
2. 计算教师 logit 标签；
3. 只更新物理专家；
4. 任务主干保持冻结。

### 8.3 阶段 C：普通 DAgger

每轮 DAgger：

1. 用当前策略在训练重力下运行闭环；
2. 收集当前策略实际访问到的状态；
3. 用教师控制器重新给这些状态打标签；
4. 将新状态加入数据集；
5. 继续更新物理专家。

V19 完整配置为 3 轮 DAgger，每轮每个训练重力运行 32 个 episode。

### 8.4 阶段 D：失败优先 DAgger（V27）

V27 对新插值专家使用失败状态加权：

- 保存所有闭环访问状态；
- 对最终未成功的 episode 状态额外复制 3 次；
- 失败状态在训练采样中约占更高比例；
- 只更新新增物理专家；
- 任务主干和原有专家冻结。

这是当前更可靠的闭环改进方法。

### 8.5 当前没有采用的阶段：可微成功率微调

V27 还测试了通过可微动力学直接优化软成功率，但结果不稳定，会改善某些插值点、破坏另一些插值点，因此暂时不进入主训练流程。

## 9. 损失函数

当前主要使用模仿损失：

```text
L_imitation = MSE(l_pred, l_teacher)
             + 0.1 * MSE(tanh(l_pred), tanh(l_teacher))
             + 0.01 * Softplus(-sign(l_teacher) * l_pred)
```

它主要约束动作 logit 和动作方向，不直接优化：

- 最终 episode 是否成功；
- 最高杆端高度；
- 成功所需步数；
- 长时闭环稳定性；
- 对动力学扰动的鲁棒性。

这正是当前“动作误差很小但闭环仍可能失败”的重要原因。

## 10. 在线适应实验

实现文件：`experiments/v24_corrected_online_adaptation.py`

V24 使用的顺序为：

```text
7.35 -> 14.7 -> 12.25 -> 7.35
```

每到一个重力环境：

1. 收集当前策略访问状态；
2. 使用该重力对应教师重新标注；
3. 只更新当前激活物理专家；
4. 检查旧环境性能是否下降。

快速实验观察到：

- 新环境可以通过局部专家适应；
- 返回旧重力后性能可以恢复；
- 没有明显灾难性遗忘。

但当前仍然是短序列、单随机种子的 proof-of-concept，不足以宣称已经完成真正的在线持续学习。

## 11. 路由和责任消融

当前比较过三类策略：

### 11.1 No routing

只使用任务主干：

```text
l = l_task
```

它不能根据物理参数变化调整动作。

### 11.2 Global routing

所有物理专家在每个非名义条件下都获得非零权重和梯度。它可以提高某些成功率，但参数责任不清晰。

### 11.3 Local routing

使用 B 样条局部基函数。训练节点对应的梯度责任接近严格局部：

```text
g=7.35  -> 主要更新对应低重力专家
g=12.25 -> 主要更新对应中间专家
g=14.7  -> 主要更新对应高重力专家
```

这是当前结构最明确的可解释性证据。

## 12. 当前实验结果和解释

固定 20 个初始状态、500 步 horizon 的代表性结果：

| 重力 | 教师 | V19 局部路由 | V27 失败优先 DAgger |
|---:|---:|---:|---:|
| 7.35 | 20/20 | 19/20 | 19/20 |
| 9.80 | 20/20 | 18/20 | 18/20 |
| 11.00 | 20/20 | 17/20 | **19/20** |
| 12.25 | 20/20 | 20/20 | 20/20 |
| 13.475 | 20/20 | 17/20 | **18/20** |
| 14.70 | 20/20 | 18/20 | 18/20 |
| 17.15 | 18/20 | 9/20 | 9/20 |

由此可以分离出三种不同问题：

1. `g=9.8` 的 18/20：任务主干和有限动作拟合问题；
2. `g=11.0`、`g=13.475`：未见参数的插值和闭环分布偏移问题；
3. `g=17.15`：超出训练范围的外推问题，并且教师自身只有 18/20。

认知 code 与 oracle code 的成功率接近，因此当前认知编码不是主要性能瓶颈。

## 15. 当前框架的准确论文表述

目前最严谨的表述是：

> 我们提出一个任务策略与物理适应参数分离的控制框架。任务主干负责学习名义任务行为，局部 ProtoKAN 物理专家通过物理条件路由产生残差修正。一个基于下一状态预测的世界模型用于提取物理变化编码，并将其接入决策网络的物理解码器。初步实验显示，局部物理责任分配和失败优先 DAgger 可以改善未见物理参数的插值泛化。

目前不应表述为：

- ProtoKAN 已经显著优于 MLP；
- 已经实现完全端到端认知决策；
- 已经验证复杂环境中的通用在线持续学习；
- 所有物理参数变化都能稳定外推。
