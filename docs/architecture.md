# KAN 结构驱动层次化决策架构

## 0. 核心转变

**之前**：把 KAN 当作数值预测器 `f(s,a) → s'`，反复调用它做前向推演。

**现在**：把训练好的 KAN **解剖**成五个独立的知识模块，每个模块直接参与规划问题的**结构化改造**。KAN 不负责数值推演——那个工作外包给 MLP。

```
传统用法:                        新架构:
s,a → [KAN] → s'                s,a → [MLP] → s'    （数值推演，MLP 做）
                                      ↑
                                 [KAN] 提供：
                                 因果结构、Jacobian 方向、
                                 不确定性、安全边界、
                                 符号公式结构
```

---

## 1. 离线：五层知识提取

从 CWS 训练的 KAN 中提取：

| 层 | 知识模块 | 提取方法 | 数学产出 |
|------|------|------|------|
| 1 | 稀疏因果图 | 剪枝 → 二值连接矩阵 → 谱聚类 | 每个动作的作用域、解耦子空间 |
| 2 | 局部线性模型 | B-样条导数 $\phi'_l(x)$ + 网络结构 | Jacobian 函数（cos_sim≈0.98）、饱和/死区边界 |
| 3 | 不确定性与 Lipschitz | 样条控制点激活密度 $\rho(x)$、$\|\phi'_l\|_\infty$ | $U(s,a)$ 函数、全局 Lipschitz 常数 $L$ |
| 4 | 可加性归因 | 节点求和天然可分解 | 每个输入对每个输出的绝对/相对贡献 |
| 5 | 符号公式 | 对每条边做符号回归 | $\mathcal{F}(s,a)$、可分离物理参数 |

---

## 2. 在线：三步决策循环

每步执行：**不确定性估计 → 模式选择 → 安全投影**

### 2.1 模式选择

计算 $u = U(s_t, a_{\text{nom}})$：

| 条件 | 模式 | 运动模型 | KAN 的角色 | MLP 的角色 |
|------|------|------|------|------|
| $u < \eta$ 且符号公式可用 | A: 解析规划 | $\mathcal{F}(s,a)$ | 提供符号结构 | 不需要 |
| $u < \eta$ 但无符号公式 | B: KAN 增强 MPC | $f_{\text{MLP}}(s,a)$ | 提供方向、约束、初始化 | 纯数值推演 |
| $u \ge \eta$ | C: 安全回退 | decision_v3 策略 | 训练时提供了梯度 | 不需要 |

### 2.2 模式 B 的详细流程（最常用模式）

**这是最体现架构设计的地方。**

**步骤 1: 问题降维（层1 驱动）**
- 因果图识别与目标相关的动作子集 $\mathcal{A}_{\text{active}}$
- 无关动作固定为标称值，优化变量减少

**步骤 2: 优化初始化（层2+层4 驱动）**
- 用 Jacobian $B_t$ 计算最速下降方向：$\Delta a = \eta B_t^T(s_g - s_t)$
- 层4 的归因信息对贡献大的动作维度加权放大
- 这个初始化将后续优化迭代次数降低 50%+

**步骤 3: 带结构约束的 MPC（层2+层3 约束）**
- **前向推演**：完全由 MLP 执行，KAN 不参与 → 无累积误差
- **动作饱和约束**（层2）：$a^{(j)} \in [a_{\min}(s), a_{\max}(s)]$（不能进入死区）
- **信任域约束**（层3）：$\|a_t - a_{t-1}\| \le \delta/L$
- **不确定性惩罚**（层3）：$\lambda_U \cdot U(s,a) \cdot \|\Delta a\|^2$ 加入代价函数

### 2.3 安全投影（所有模式通用）
- 激活函数饱和截断（层2）
- Lipschitz 变化率约束（层3）
- 前瞻检查：若执行后 $U$ 超标，回退到 decision_v3

## 3. 持续学习闭环

环境变化时的完整流程：

```
环境变化 → KAN 预测误差增大 → U(s,a) 飙升
    → 自动切换模式 C（安全策略接管，系统不倒）
    → 后台收集 (s,a,s') → 局部微调受影响边的样条控制点
    → U(s,a) 逐渐回落
    → 自动切回模式 A/B（高性能恢复）
```

**为什么这比纯 KAN-MPC 更好**：
- 纯 KAN-MPC：环境变化 → KAN 不可靠 → 整个系统瘫痪（唯一预测器失效）
- 新架构：环境变化 → KAN 不可靠 → 安全策略接管 → KAN 在后台安全学习 → 恢复

## 4. 与实验证据的对应

| 你的实验发现 | 架构如何利用 |
|------|------|
| KAN 数值精度不足（vs MLP 43× 差距） | 数值推演外包给 MLP，KAN 只提供结构 |

| decision_v3 已 100% | 保留为模式 C 的安全兜底策略 |
| KAN 可解释性（边函数、控制点） | 每一层知识都在运行时参与决策 |

## 5. 设计哲学

**KAN 的精度问题不再是 bug，而是驱动这个架构分工的契机。**

MLP 做计算（数值推演），KAN 做思考（结构、方向、边界、自知）。两者互补，各司其职。MLP 在这个架构里是可替换的——可以是另一个模型、真实环境、或未来精度追上后的 KAN 自身。

**KAN 的独特贡献**：没有 KAN，这个架构无法存在——MLP 提供不了 Jacobian 方向、认知不确定性、可认证导数上界、符号公式、持续学习不遗忘。这些正是你从一开始选择 KAN 的原因。这个架构就是为这些独特能力量身定做的操作系统。
