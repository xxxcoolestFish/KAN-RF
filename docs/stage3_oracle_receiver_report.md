# 阶段三：决策网络物理接收器的 oracle 验证

## 实验目的

在把认知网络接入之前，先回答一个结构问题：决策网络中显式的物理接收子空间是否真的能使用外部传入的物理码。决策网络保持同一结构：状态经过 task trunk，物理码通过 `physics_basis` 调制 action head。

本实验不是最终 Acrobot 成功率实验，而是接收器的功能性单元测试。

## 初始教师失败

最初使用三步恒定动作、最大化末端高度的离散教师。300 步训练后 state-only 和 oracle 的 MSE 都约为 `0.9`，说明教师目标对当前 ProtoKAN 决策头过难或监督信号不足；因此没有把该结果解释为接收器失败。

## 平滑条件控制 probe

随后使用一个连续的 state--physics 交互目标作为结构 probe：

\[
a^*=\tanh\bigl(
0.25\dot\theta_1+0.60 c_1\dot\theta_1
+0.45 c_2\dot\theta_2
+0.45 c_3\sin\theta_1
-0.45 c_4\sin\theta_2
\bigr),
\]

其中 `c` 是由隐藏重力、阻尼、驱动强度和惯量尺度归一化得到的 oracle 物理码。训练只使用训练因素组合，测试使用两个未见组合。state-only 对照接收全零物理码。

## 混合 held-out 结果

| seed | 模式 | MSE | receiver 打乱后 MSE | 打乱增量 |
|---:|---|---:|---:|---:|
| 42 | state-only | 0.06947 | 0.06947 | 0.00000 |
| 42 | oracle | **0.04243** | 0.09097 | **0.04854** |
| 43 | state-only | 0.07408 | 0.07408 | 0.00000 |
| 43 | oracle | **0.03874** | 0.08628 | **0.04754** |

## 结论

1. 显式物理接收器能够利用传入的物理码：oracle 比 state-only 的误差降低约 39%（seed 42）和 48%（seed 43）。
2. 打乱物理码显著破坏 oracle 性能，而对 state-only 没有影响，说明性能提升不是额外参数量或随机初始化造成的，而是来自接收器输入。
3. 这只验证了“决策侧准备好了接收物理知识”的结构命题；oracle 码仍是人为可访问的隐藏因素，尚未证明认知网络输出的 `c(h)` 能达到同样效果。

## 下一步

冻结已校准的低秩认知编码器，先把其物理系数 `c(h)` 接到同一个决策接收器，并与 oracle、state-only、随机物理码三组对照。只有认知输入接近 oracle，才有理由继续做联合训练和参数级 transport 算子比较。
